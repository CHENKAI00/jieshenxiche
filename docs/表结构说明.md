# `js_member` 字段说明（17 字段，一行 = 一辆车）

> v3：`total_count` 已拆成 `wash_count`（洗车）/ `wax_count`（打蜡），`last_amount` 已删除。

先记住三件事，整张表就好懂了：

1. **一行 = 一辆车 = 一个会员**，`plate_no`（车牌）是业务主键，拍照识别就是拿它查这一行。
2. 表只回答三个问题：**这车是谁的**（身份）、**还剩多少钱 / 多少次**（钱与次数）、**最近来过没有、做了什么**（最近动态）。
3. 不存流水明细（店主定的），所以历史和账目只保留「最近一次」。

---

## 一、身份组：这车是谁的

| 字段 | 类型 | 含义 | 示例 | 谁写入 |
| --- | --- | --- | --- | --- |
| `id` | INT UNSIGNED 自增 | 行号，内部主键 | `1` | 数据库 |
| `plate_no` | VARCHAR(16) 唯一 | 车牌，**唯一检索键**；统一大写、去空格/点/横线、7 或 8 位 | `粤B12345`、`粤BD12345` | 建档、纠正车牌 |
| `plate_color` | VARCHAR(8) | 车牌颜色：蓝 / 绿（新能源）/ 黄 | `绿` | OCR 回填或校验函数推断 |
| `member_no` | VARCHAR(24) | 会员卡号，给车主报号用 | `JS2611154821` | 建档时自动生成 |
| `nickname` | VARCHAR(32) | 车主称呼 | `张先生` | 建档 / 可改 |
| `phone` | VARCHAR(20) | 手机号（11 位），接口返回自动脱敏 | 库内 `13800138000`，接口 `138****8000` | 建档 |

细节：

- **`plate_no` 为什么唯一**：拍照识别结果是脏的（O/0、I/1 混淆），全靠归一化 + 唯一索引兜住，避免同一辆车建出两条档案。识别纠偏在 `src/utils/plate.js`：全角转半角 → 去空格·- → 大写 → O→0 / I→1 / S→5 → 校验省简称 + 发牌机关字母。
- **`plate_color`** 只用于展示（结果卡片显示「车牌颜色 绿」），**不参与计价**。判断规则：8 位且序号位含 `D/F` → 绿；末位是 挂/学/警/港/澳/领/试/超 → 黄；其余 → 蓝。
- **`member_no` 不唯一**（随机 4 位可能撞），因为检索永远走车牌，卡号只是给客人看的号；要严格唯一可给它加唯一索引。
- **`phone` 能重复**：一家人两辆车用同一个手机号是常态，所以 `idx_phone` 是普通索引不是唯一索引。

## 二、钱与次数组：还剩多少

| 字段 | 类型 | 含义 | 示例 | 什么时候变 |
| --- | --- | --- | --- | --- |
| `balance` | DECIMAL(10,2) | 储值余额（元），**全表唯一的钱** | `268.50` | 充值加、核销扣 |
| `remain_count` | INT | 次卡剩余次数，**通用计数，不分项目** | `3` | 充值赠次、核销扣次 |
| `wash_count` | INT | **洗车次数**（只有配置为「洗车+1」的项目才累加） | `27` | 核销洗车类项目 +1 |
| `wax_count` | INT | **打蜡次数**（只有配置为「打蜡+1」的项目才累加） | `4` | 核销打蜡 +1 |
| `expire_at` | DATE | 次数有效期，空 = 不过期 | `2026-12-31` | 充值买次卡时按“月数”推算 |

三个数字别搞混：

| 你要回答的问题 | 看哪个字段 |
| --- | --- |
| 这车还能花多少钱？ | `balance` |
| 这车还能免费洗 / 打蜡几次？ | `remain_count` |
| 这车洗过多少次？ | `wash_count`（历史累计，不因扣次减少） |
| 这车打过多少次蜡？ | `wax_count`（同上） |

核销顺序（`services/member.js` 的 `consume`）：**先扣次数（且未过期），次数为 0 或已过期就扣余额**；余额不够直接返回 402，不会扣成负数。判断和扣款在同一个事务里 `SELECT ... FOR UPDATE`，两前台同时扫同一辆车也不会重复扣。

**按项目计次**：每个项目在 `data/services.json` 里有 `countKey` —— `wash` 核销时 `wash_count+1`，`wax` 核销时 `wax_count+1`，
`null` 的项目（抛光 / 内饰清洁 / 玻璃镀膜 / 新车开蜡）只扣钱不计数。后台「项目管理」里随时可改这三选一。

`expire_at` 到期后 `remain_count` 数字还在，但核销不再走次数，改按余额计价（小程序会显示「次数卡已于 xx 到期」的提示）。

## 三、最近动态组：最近来过没有

| 字段 | 类型 | 含义 | 示例 | 谁写入 |
| --- | --- | --- | --- | --- |
| `last_service_at` | DATETIME | 最近一次**核销**的时间，不是建档/充值时间 | `2026-11-15 20:31:00` | 核销时 `NOW()` |
| `last_item` | VARCHAR(32) | 最近一次核销的服务项目名 | `打蜡` / `精洗SUV/MPV` | 核销时写入 |

这一组是「取代流水表」的三个字段，语义很关键：

- **只有核销会写这两个字段**；建档不写、充值不写。所以「最近一次」永远是**真实的到店服务**，不会出现「最近一次 = 充值 ¥200」这种脏数据。
- `last_amount` 已按店主意见删除（不需要「最近实收」），看板也不再统计「今日实收」，改为看「今日到店 / 今日新客 / 累计洗车 / 累计打蜡」。
- **局限（店主已知）**：只留最近一次，同一辆车当天来两次，只留下第二单；查不到三个月前的记录，也没有营业额汇总。要日结报表/对账，就得再开第二张 `js_order` 流水表。

## 四、运营组：备注与审计

| 字段 | 类型 | 含义 | 示例 |
| --- | --- | --- | --- |
| `remark` | VARCHAR(255) | 门店备注，核销/充值时带 note 会覆盖（空则保留原值） | `新能源，充电口别冲水` |
| `status` | TINYINT | 1 正常 / 0 停用（预留） | `1` |
| `created_at` | DATETIME | 建档时间，默认 `CURRENT_TIMESTAMP`，用于「今日新客」 | `2026-11-15 10:00:00` |
| `updated_at` | DATETIME | 自动 `ON UPDATE`，排障看这一行最后啥时候被改 | — |

- `status` 目前**接口还没做过滤**（会员名录、看板都会算上停用会员）；真要停用，需要在 `listMembers` / `overview` 加 `WHERE status = 1`。
- `remark` 是唯一「店主自由文本」的地方，适合写车况禁忌（只洗外观、别冲充电口、豪车用软水）。

## 五、拿一条真实数据逐字段读

`粤A66666 / 王先生`：

```
id=3, plate_no=粤A66666, plate_color=蓝, member_no=JS2026003,
nickname=王先生, phone=13700137000,
balance=108.00, remain_count=2, wash_count=10, wax_count=3, expire_at=2026-11-30,
last_service_at=2026-11-15 20:31:00, last_item=打蜡,
remark=喜欢打蜡，每月一次, status=1, created_at=…
```

翻译成人话：**王先生这辆车，卡上还剩 108 元、次卡还剩 2 次没用、累计洗车 10 次、打蜡 3 次，最近一次是今天来打蜡，卡到 11 月 30 日有效，备注是「喜欢打蜡，每月一次」。**

## 六、三个动作到底改了哪些字段

| 动作 | `balance` | `remain_count` | `wash_count` | `wax_count` | `expire_at` | `last_*` 两件套 |
| --- | --- | --- | --- | --- | --- | --- |
| 建档 | 0 | 0 | 0 | 0 | 空 | 空 |
| 充值 ¥200 送 ¥30 + 10 次 12 个月 | +230 | +10 | 不变 | 不变 | 按 12 个月推算 | **不动** |
| 核销·洗车（扣次数） | 不变 | −1 | **+1** | 不变 | 不变 | 时间=现在 / 项目=标准洗车 |
| 核销·打蜡（扣余额 ¥98） | −98 | 不变 | 不变 | **+1** | 不变 | 时间=现在 / 项目=打蜡 |
| 核销·抛光（不计数） | −180 | 不变 | 不变 | 不变 | 不变 | 时间=现在 / 项目=抛光 |

## 七、索引与约束为什么这么建

```
PRIMARY KEY (id)                    -- 行标识
UNIQUE KEY  uk_plate_no (plate_no)  -- 拍照识别后精确命中一行；同时防重复建档
KEY idx_phone (phone)               -- 按手机号反查（一家人多辆车）
KEY idx_last_service (last_service_at) -- 「最近到店」列表排序
```

`plate_no` 是 `VARCHAR(16)` 而不是 `CHAR`：新能源 8 位、普通 7 位，长短不一，`VARCHAR` 更省。

## 九、常见问题

**Q：一辆车两个人开、两个手机号怎么办？**
当前模型是一车一会员一手机号。家庭卡需求要么把手机号放 `remark`，要么加 `phone2` 字段。

**Q：车主换车牌了？**
`UPDATE js_member SET plate_no='新牌' WHERE id=?`，余额和次数跟人走。注意唯一索引会拦住“新牌已被别人占用”的情况。

**Q：次数能不能分项目（洗车 10 次 + 打蜡 3 次）？**
`remain_count` 是「次卡剩余次数」，核销任意项目都扣 1 次（通用）。而 `wash_count` / `wax_count` 是**历史累计**，不参与抵扣。
要「洗车 10 次 + 打蜡 3 次」各自独立的余额，需要把 `remain_count` 拆成 `wash_left` / `wax_left` 两列。

**Q：抛光、内饰清洁为什么不计数？**
它们在后台的计次规则是「不计数」，只扣钱并记录 `last_item`。想统计就在后台把该项目改成「洗车+1」或「打蜡+1」。

**Q：金额会不会出现浮点误差？**
不会。`DECIMAL(10,2)` 定点存储，上限 99,999,999.99；代码里所有加减都 `Math.round(x*100)/100` 后再入库，不用 float。

**Q：余额会被扣成负数吗？**
不会。先在同一事务里 `SELECT ... FOR UPDATE` 锁行、比较余额、再更新；不足直接 402。

**Q：怎么自己看线上表结构？**
```sql
SHOW FULL COLUMNS FROM js_member;      -- 字段 + 注释
SHOW CREATE TABLE js_member\G          -- 完整 DDL + 索引
SELECT * FROM js_member\G              -- 竖排看一行，字段多时更清楚
```
